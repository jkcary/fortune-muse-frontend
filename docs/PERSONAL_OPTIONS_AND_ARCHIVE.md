# Personal AI exercises, saved action work, calendar and collection

Door exercises now generate their questions and 3–4 options per group from the immutable user question/context and chosen path through the configured `intake` AI task. They no longer render the fixed priority/cost catalogue. After both choices, a second model call generates the summary and concrete reflection question from those exact labels and the original context. Model failures show a retry; no fixed substitute is presented. A successful option set is cached once per reading. Reflections are cached per pair. Stored content keeps its original language and provider/model attribution across reloads and locale changes.

`POST /oracle/casts/:id/door-exercise` requires reading access, a completed cast and a chosen door. Its optional selection references generated IDs. Generation coalesces within a process, uses a cross-worker advisory lock, bounds concurrent work, and checks expiry before committing. It updates only its own JSON column so concurrent story edits remain intact. Successful options have version 1. Saving them through the existing journey endpoint verifies membership in the cached set. Old enum choices remain readable, but are not rendered as personal options; an outdated client cannot overwrite the new choice format after generation. The chosen door remains locked.

The action section has a separate 6,000-character My next-step work field for lists, names and problems, message drafts or checklists. Explicit saving stores `journey.actionNotes` independently of the action instruction and progress-update history, without enabling memory or following the story. It can be edited or cleared. Guest/private work retains the reading's existing expiry; an account-owned permanent story persists it. Account export/deletion includes it through journey JSON. It is excluded from public card exports and AI exercise input.

The closing keepsake now has a centred portrait card as its main visual, with the guide, download options and actions below. Export content and the explicit personal-quote checkbox remain unchanged. Closing, journal and navigation provide calendar and collection entrances.

`/calendar` groups saved completed permanent account readings by local date and supports month navigation, day filtering and pagination. `/collection` shows favorites by default, offers all saved cards, and adds/removes favorites using the existing reading endpoint. Collection cards preview the actual public closing card and link back to the reading. The archive never includes guest, private, expiring, incomplete or another account's records. Pages beyond the old 100-reading journal limit remain accessible. Calendar counts cover the whole month even when list results are paginated. Personal questions/action work are not included in card previews.

## Deployment and validation

Apply additive migration `015_ai_door_exercise.sql` after 014 before serving the new API. It adds nullable `oracle_casts.door_exercise_json`. Account exports now include that column. No payment, coin or subscription changes are involved. Run `npm run contracts:sync` after changing the shared contract.

The new `/oracle/archive` endpoint accepts validated month/day, favorites, optional hexagram and page filters. It authenticates the user, uses the existing timezone header with a validated fallback and returns month markers, totals, distinct hexagram counts, paginated casts and a next-page flag.

Validation: 135 backend tests pass. Coverage includes contextual AI input, cached/coalesced generation and reflections, failure/retry without template substitution, choice membership, access/expiry during generation, action-work persistence/concurrent generation/export/deletion, month boundaries in Los Angeles, invalid dates, exclusion rules, favorite changes and 105-record pagination. The real configured provider was exercised with a synthetic name-card question, producing Chinese options and a choice-specific reflection; the synthetic guest reading was removed afterward. Browser checks cover saved work and choices after refresh, centred keepsakes, archive pagination, day selection, favorite changes and persistence, 320px layouts and both Chinese variants. Scripts/screenshots are in ignored `output/playwright/personal-*` files. Web/iOS/Android resource exports pass; physical device storage/audio acceptance remains separate.
