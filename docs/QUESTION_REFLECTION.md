# Scientific key-point reflection for an open question

Selecting An open question and pressing the keep/read button now sends the user's thought, reported fact, concern and chosen UI language to `POST /garden/question-reflection`. No AI call occurs merely on entry or category selection. The configured intake provider returns exactly three personalised points: evidence and its limits, an unverified explanation/uncertainty, and a small observable check or a request for missing information. Prompts require precise calibrated language, preserve negation and timing, distinguish reported facts from independent verification, prohibit unsupported causal/intent claims, and do not invent worries for ordinary positive experiences. This endpoint does not use a hexagram or astrological reasoning.

The entire displayed numbered analysis, including spaces, numbering, newlines and punctuation, is validated against a 200-Unicode-code-point cap. Invalid, overlong, offline or failed responses produce a retryable error rather than a fixed fallback or silent truncation. Successful results show AI attribution and their character count.

The request is bounded, rate limited, safety screened and coalesced for concurrent identical inputs/identity; at most three generations run per process. Authenticated requests validate their bearer identity. Guests can use the same stateless reflection. No schema migration is needed, and input/output are not stored in the garden tables or account memory. The page explains that question text is sent to AI. Provider retention still follows the deployment/provider policy.

After AI success, the existing daily category action runs only if today's moment is not already kept. A previously kept joy/discovery does not block reflection on a new open question and is not overwritten or counted twice. The prior category's stock feedback is hidden when it differs from the current selection. Question inputs remain available for reviewing and editing. A changed input/language hides the old analysis and permits a new request. A daily-save failure preserves the analysis and retries saving without paying for a second model call. Leaving/reloading the page removes the analysis; existing category-only daily storage remains unchanged.

Other categories keep their existing behaviour and do not send draft text to AI. New interface strings support all four locales. English analyses also obey the conservative 200-character cap.

Validation: 141 backend tests pass. Coverage includes contextual input, explicit triggering, three-point output, displayed Unicode length, invalid/empty/unsafe inputs, provider failures without fallback, concurrent request coalescing, locale prompts, authentication and separation from daily persistence. Browser checks cover retry/draft retention, a failed local daily save without regenerating AI, changed-input invalidation, pre-existing daily moments, one-count persistence, no private text in guest storage and mobile layouts. Real configured AI was exercised with an unanswered-message question and the supplied positive-shopping scenario; successful examples are under 200 characters. Positive feelings are accepted as the user's experience, and a missing question prompts clarification rather than invented corrective action. Synthetic inputs and screenshots live under ignored `output/playwright/question-*` paths. Web/iOS/Android resource exports pass; installed device acceptance remains separate.
